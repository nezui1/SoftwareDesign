# Генератор учебного расписания

Учебный прототип ядра курсового проекта. Он распределяет занятия по свободным
временным слотам, учитывая занятость группы, преподавателя и аудитории.

## Запуск проверок

```bash
python -m pip install -e '.[dev]'
ruff check .
pytest --cov=scheduler --cov-branch --cov-report=term-missing
python scripts/metrics.py
```

## Работа с исходным кодом

Применяется упрощенный GitHub Flow: `main` хранит рабочую версию, а работа
по этой лабораторной ведется в ветке `lab5`. Изменения вливаются через pull
request после успешных проверок и просмотра diff. Сообщения коммитов:
`feat: ...`, `fix: ...`, `docs: ...`, `test: ...`, `chore: ...`.

Локальную проверку сообщения можно включить командой
`git config core.hooksPath scheduler_lab/.githooks`, запущенной из корня этого
репозитория. На сервере сообщения повторно проверяются в GitHub Actions. Ветка
`main` защищена: изменения проходят через pull request после успешных проверок
`verify` и `build`.

Релиз: после успешного слияния в `main` создать аннотированный тег `v0.1.0`, отправить
его на сервер и оформить Release. Тег запускает проверку и сборку пакета.
Защита ветки и релиз на сервере описываются отдельно в отчете.

Метрики: `scripts/metrics.py` записывает число строк кода, число коммитов за
7 дней, средний размер коммита, число замечаний линтера, покрытие строк и ветвей,
число пройденных и упавших тестов, а также длительность тестов. Снимки JSON
сохраняются как артефакты каждого workflow; измерения следует
запускать на контрольных этапах из лабораторной работы №3.
